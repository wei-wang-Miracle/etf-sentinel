# 单只 ETF 策略流程实施计划

本计划执行已确认的[单 ETF 设计](../specs/2026-11-07-single-etf-strategy-journey-design.md)，
包括三入口、中文条件、策略对比、版本保存、启用与每日信号。

**目标：** 持仓或未持仓 ETF 均可完成配置、比较、保存、启用和执行核对。
**架构：** 复用现有成交引擎、不可变回测与任务5；新条件注册成统一策略，历史
计算与每日决策共用。增加自定义策略版本与比较记录，原实验和观察记录保留。
**技术：** FastAPI、SQLAlchemy、Alembic、PostgreSQL、React、TypeScript、ECharts。
**执行：** 使用 subagent-driven-development 分工，业务规则按 test-driven-development
先验证失败再实现；当前目录开发，不创建工作区，保留原未提交改动。

## 2. 条件引擎、版本与比较接口

后端实现位于 `api/app/strategy_conditions.py`、`api/app/strategy_workbench.py`，
模型与迁移沿用现有目录。注册表和现有日计划只增加自定义规则必需的接入点。

- [x] 先在 `api/tests/test_strategy_conditions.py` 验证趋势、动量、波动、组内
  全部／任一、持仓退出、买卖同时触发、预热不足和未来数据不影响过去。
- [x] 条件保存指标、窗口、比较符、阈值及单位；情绪显式选择类别。
- [x] 本地估值、国家队和恐贪按明确映射与日期读取，修订历史单独标识；
  不将采集时间冒充发布时间，缺失不补零，不无限向前填充。
- [x] `GET /strategies/catalog` 返回ETF覆盖、条件元数据与适用性。
- [x] `GET /strategies`、`POST /strategies` 提供命名策略不可变版本；草稿可恢复，
  修改产生新版，不覆盖旧回测。未有效回测的配置不能启用。
- [x] `POST /strategies/comparisons` 以具体版本及可选当前草稿为对象，统一
  区间、本金、成本和数据快照运行；追加持有及半资金持有参照。
- [x] `GET /strategies/comparisons`、`/{id}`、`POST /{id}/verify` 提供比较历史、
  原结果和快照复算；失败对象保留，已保存策略与启用状态不被比较覆盖。
- [x] 独立测试库验证统一输入、半资金、不可变版本、失败保留及修订后复算。
