## 1. 背景与范围

原第一期设计按全账户复盘，但账户实际包含多只配置外 ETF、LOF 和逆回购，
且券商接口没有现金余额和完整分红流水。用户确认：

- 只收集当前 20 只配置内 ETF；
- 只做配置内 ETF 的单标的复盘；
- 不计算全账户 TWR/XIRR；
- 配置外持仓、LOF、逆回购、现金不纳入本期。

已核对配置内子集：

| 项目 | 结果 |
| --- | --- |
| 配置内 ETF 有成交 | 159205、159531、159915、510330、510500、512100 |
| 当前仍持有 | 159205、159531、510500、512100 |
| 已清仓 | 159915、510330，买卖数量净额为 0 |
| 成交净额与当前持仓 | 6 只全部一致 |
| 成交最早日期 | 2025-01-20；2024 年查询为空 |

配对规则：卖出数量不能超过前一日可用持仓；配置内 ETF 为境内股票 ETF，
按 T+1 校验。若未来配置内出现 T+0 品种，再单独登记交易规则。

**1A.1 同步与展示已实现**，复用 `account_sync.py`、`account_routes.py`、
迁移 `0008` 和 `Review.tsx`，不重建导入器、账户表或持仓页面。
后续先核验权益事件及数量，再计算真实盈亏和 XIRR，最后接入统一资金研究基线。
上述六只为已核对的历史子集，不是永久白名单；后续同步仍以 `instruments` 为准。

## 2. 已验证数据源

### 2.1 持仓接口 `mine/stockreal`

请求：

```text
POST /api/sqlapi/api-execute?api_path=mine/stockreal&access_code=...
Authorization: Bearer ...
{"fundAccount": "..."}
```

返回当前持仓快照，`data` 为数组；本期只保留配置内 20 只 ETF。实际使用字段：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `STOCK_CODE` | ETF 六位代码 | 过滤和关联 |
| `CURRENT_AMOUNT` | 当前数量 | 当前持仓 |
| `ENABLE_AMOUNT` | 可用数量 | T+1 校验 |
| `FROZEN_AMOUNT` | 冻结数量 | 数据质量 |
| `UNCOME_BUY_AMOUNT` / `UNCOME_SELL_AMOUNT` | 在途买卖 | 数据质量 |
| `COST_PRICE` | 成本价 | 对账 |
| `SUM_BUY_AMOUNT` / `SUM_SELL_AMOUNT` | 当前持仓周期的累计买卖数量 | 与成交净额对账 |
| `SUM_BUY_BALANCE` / `SUM_SELL_BALANCE` | 累计买卖金额 | 与成交金额、费用对账 |
| `DATA_DATE` | 源数据日期 | 快照唯一键 |
| `ETL_TIME` | 源更新时间 | 审计 |

接口只返回当前快照，不提供历史持仓；历史持仓由成交重建。接口没有现金余额。

### 2.2 委托/成交接口 `mine/entrust`

请求：

```text
POST /api/sqlapi/api-execute?api_path=mine/entrust&access_code=...
Authorization: Bearer ...
{"fundAccount": "...", "startDate": "YYYYMMDD", "endDate": "YYYYMMDD"}
```

返回区间内的委托记录，包含成交数量和成交价。已验证：

- 单次最多返回 **1000 行**，按日期升序；宽区间会截断。
- 2025-01-20 ～ 2026-02-05 返回 1000 行，2026-02-05 单日还有 11 行，
  说明该窗口在 2026-02-05 被截断；需要单日补口。
- 2026-02-06 ～ 2026-05-31 返回 825 行；2026-06-01 ～ 2026-11-05 返回 527 行。
- `ENTRUST_NO` 不是全局唯一，同一号码可能出现在不同日期/标的；
  唯一键使用 `(CURR_DATE, ENTRUST_NO)`。
- `ENTRUST_STATUS` 观测值为 `8`、`6`、`2`，源未提供状态字典；不硬编码中文状态，
  以成交数量、撤单数量和原始状态共同判断。

实际使用字段：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `CURR_DATE` / `CURR_TIME` | 委托日期/时间 | 日期级复盘；时间不是逐笔成交时间 |
| `INIT_DATE` | 委托发起日 | 审计 |
| `ENTRUST_NO` / `ORDER_ID` | 委托编号 | 去重 |
| `STOCK_CODE` | ETF 代码 | 过滤 |
| `ENTRUST_BS` | 1 买、2 卖 | 买卖方向 |
| `ENTRUST_AMOUNT` / `ENTRUST_PRICE` | 委托数量/价格 | 执行偏差 |
| `BUSINESS_AMOUNT` / `BUSINESS_PRICE` | 成交数量/价格 | 实际成交 |
| `BUSINESS_BALANCE` | 成交金额 | 成交金额 |
| `CLEAR_BALANCE` | 清算金额 | 与成交金额差额推导费用 |
| `WITHDRAW_AMOUNT` | 撤单数量 | 撤单识别 |
| `ENTRUST_STATUS` / `FARE_KIND` | 原始状态/费用类别 | 审计 |
| `DATA_DATE` / `ETL_TIME` | 源数据日期/更新时间 | 增量与审计 |

源记录是委托级累计成交，不是逐笔成交回报。后续复盘只使用有效买卖方向且
`BUSINESS_AMOUNT > 0` 的累计成交量和金额；源修订覆盖后的委托只计一次。
`CURR_TIME` 不用于声称精确成交时刻或计算分钟级执行延迟。若不能确认成交所属
交易日与 `CURR_DATE` 一致，相关记录先标记不可用于日级复盘，不猜测成交日期。

### 2.3 费用推导

对已成交记录：

```text
买入费用 = CLEAR_BALANCE - BUSINESS_BALANCE
卖出费用 = BUSINESS_BALANCE - CLEAR_BALANCE
```

配置内 6 只 ETF 全部成交的推导费用约 158.51 元。该费用是源字段推导值，
不是券商逐笔费用明细；页面必须标注“推导费用”，并允许后续用对账单覆盖。

### 2.4 分红源

使用现有东方财富权益页：

```text
https://fundf10.eastmoney.com/fhsp_{code}.html
```

已验证 6 只配置内 ETF 页面均存在：

| 代码 | 分红 | 拆分 |
| --- | --- | --- |
| 510500 | 有 | 有 |
| 512100 | 有 | 有 |
| 510330 | 有 | 有 |
| 159205 | 暂无 | 暂无 |
| 159531 | 暂无 | 暂无 |
| 159915 | 暂无 | 2011 年拆分，复盘区间外 |

现有解析器对“暂无分红信息!”行会报结构错误，需要支持显式无事件：

- 表头存在且行内容为“暂无分红信息!”或“暂无拆分信息!”时，返回空列表；
- 允许“无分红但有拆分”或“两者都无”，不把无事件当采集失败；
- 保留源 HTML 摘要和采集时间，便于复核；
- 复盘区间外的拆分不参与计算，但保留源事件。

## 3. 范围过滤与增量同步

### 3.1 过滤

- 账户接口会返回配置外 ETF、LOF、逆回购等记录；本期只保留配置内 20 只。
- 过滤在入库前完成；当前批次累计非配置记录跳过条数，不保存配置外明细。
- 持仓快照只保存配置内当前持仓；成交只保存配置内委托/成交。

### 3.2 初始同步

- 当前实现首次成交起点固定为 2025-01-20，同步截至北京时间当日。
  收益复盘另取成交、行情和权益事件均已核验的截止日，不把当日快照当作收盘持仓。
- 当前按不超过 30 个自然日窗口抓取；若窗口返回 1000 行，自动二分日期直到小于 1000。
  单日仍达上限则报错，不能假定补口已经完整。
- 对 2026-02-05 这类被截断的边界日做单日补口，再按 `(CURR_DATE, ENTRUST_NO)`
  去重。
- 初始同步完成后，用配置内 `stockreal` 的累计买卖数量和当前持仓对账。

### 3.3 增量同步

- 从本地最大 `CURR_DATE` 往前重叠 7 个自然日重新抓取，处理源修订和补录。
- 新数据按 `(CURR_DATE, ENTRUST_NO)` 幂等写入；重复行不新增。
- `stockreal` 每次抓取当前快照，按 `DATA_DATE` 保存；同一日期重复抓取保留
  最新快照并记录采集时间。
- 单次同步记录窗口、抓取数、入库数、跳过数、错误和耗时。

### 3.4 失败与恢复

- 401/403：凭据失效，停止并提示轮换 token。
- 429/5xx/网络错误：有限重试；仍失败则保留上次成功水位。
- 窗口返回 1000 行：视为可能截断，必须拆分；不能把截断当完整。
- 当前实现可保留合法行并记录错误，批次标为部分错误。收益复盘必须检查未解决错误、
  失败和区间缺口；本地最大成交日期不是“此前历史已完整”的证明。
- 后续复盘准入增加完整同步区间检查，错误未解决不能仅凭数量对得上就输出收益结论。
- 日志不打印 token、资金号、设备信息和完整成交明细。

## 4. 数据模型

现有迁移 `0008` 已建立下列同步表，继续复用，只存配置内 ETF。后续新增字段或
表必须通过迁移，并有中文 COMMENT；复盘区间暂按请求计算，不先建占位表。

| 表 | 职责 | 关键字段 |
| --- | --- | --- |
| `accounts` | 本地账户标识 | 账户编号、显示名称、本位币、建立时间；不保存资金号 |
| `account_sync_runs` | 同步批次 | 批次号、账户、区间、状态、抓取/入库/跳过数、错误摘要、开始/结束时间 |
| `account_holdings_snapshots` | 当前持仓快照 | 账户、数据日期、ETF 代码、当前/可用/冻结/在途数量、成本价、累计买卖数量/金额、源更新时间、采集时间 |
| `account_entrusts` | 配置内委托/成交 | 账户、委托日期/时间、委托编号、ETF 代码、买卖方向、委托/成交数量价格、成交金额、清算金额、撤单数量、原始状态、推导费用、源数据日期/更新时间 |

规则：

- `account_entrusts` 唯一键 `(account_id, curr_date, entrust_no)`。
- 只有 `business_amount > 0` 的记录进入实际成交；零成交但状态有效/撤单/废单的
  记录保留供委托状态核对；没有独立信号日志，不能推断漏单或策略执行偏差。
- `fee_amount` 为推导值；保留 `FARE_KIND` 和源状态，允许后续对账覆盖。
- `account_holdings_snapshots` 唯一键 `(account_id, data_date, instrument_code)`。
- 不存资金账号、股东账号、客户姓名、设备/IP/MAC、`POSITION_STR`、`CHECK_STR`。
- 不新增现金表；本期不做全账户 TWR/XIRR。

## 5. 比较目的与可比边界

本期区分真实交易、标准化研究和未来信号执行三类问题，不用一个收益排名混合解释。

| 层次 | 资金与输入 | 展示结果 | 允许的结论 |
| --- | --- | --- | --- |
| 真实交易结果 | 实际买卖现金流、重建持仓、权益事件 | 净盈亏金额、分项、XIRR、实际买卖标记 | 这只 ETF 的交易结果如何 |
| 标准化规则研究 | 同一初始研究资金、起止日、费用和权益口径 | 持有、MA20、MA60、现金的净值与回撤 | 固定规则相对持有的收益和风险如何 |
| 信号执行复盘（后续） | 当时信号日志、目标数量、可执行时点、实际成交 | 匹配状态和执行偏差 | 是否按当时计划执行 |

关键约束：

- 真实交易资金随买卖改变，卖出所得可能用于其他标的。缺少独立资金分配账时，
  不给这只 ETF 假设一个现金账户，不生成“真实净值”或真实最大回撤。
- 实际盈亏金额与固定资金策略盈亏不能直接相减，XIRR 与策略区间收益也不能混排。
  即使双方都有 XIRR，现金流路径不同，差额仍不是纯择时贡献。
- 首笔买入数量后一直持有只能作为“首笔投资参考”，本期不作为默认实际对照基线。
- 曾经卖出后空仓是实际决策，不是历史数据缺失；保留完整交易时间轴和累计盈亏。
  从未交易的标的没有真实交易收益，只显示研究基线。
- 没有真实信号日志时，系统 MA20/MA60 不代表用户自己的策略。

## 6. 真实交易核算

当前实现要求在请求中显式确认同步起点前零持仓和成交所属日期，其他质量门槛
仍自动核验；拆分暂严格拒绝，同日双向累计委托不猜测成本分解。

### 6.1 准入、区间与重建

先验证数据完整性，再输出相应指标。数量一致是必要条件，不能证明缺失的往返
交易、分红或费用都已补齐。

- 后端直接读取完整 `account_entrusts`，不能用默认 30 天、最多 500 行的展示接口
  计算收益；不在前端根据已加载表格行求收益。
- 根据同步覆盖、错误、权益事件和持仓快照建立可复盘区间。快照、成交与行情逐项
  返回各自截止日；明确有效开始、结束及截短原因，不自动按各条曲线分别截短。
- 历史数量由有效买卖和拆分/折算重建，按共同数据日期与持仓快照对账；同日有
  在途或未完成更新时标记待确认。当前成本价仅作源口径参考，不倒推历史买入成本。
- 不能证明历史起点零持仓时，不把首笔可见买入认作建仓起点。需要核验期初数量和
  市值；缺历史成本只阻止成本分解，不阻止有充分市值依据的区间现金流收益。
- 任意子区间从起点前最近有效收盘估值开始，含起点日至结束日成交及内部权益；
  期初数量来自完整历史重建，不能先过滤成交再假设零持仓。
- 所选结束日是所有研究基线的共同截止；已清仓 ETF 仍保留到该日的交易时间轴。
  实际 XIRR 同时返回首末有效现金流日期，不把清仓后的零现金流尾段解释为现金收益。
- T+1 核验按可用旧仓执行，当日新买不能卖；委托聚合数据不足以确认的同日顺序
  标记待核验，不按委托编号猜成交先后。拆分导致的数量变化不算真实买卖。

### 6.2 现金流与 XIRR

从 ETF 投资项目的视角计算现金流，买卖资金不是全账户出入金。

```text
区间期初：负现金流 = 期初持仓市值 + 期初分红应收（若有）
买入：负现金流 = 成交金额 + 推导费用
卖出：正现金流 = 成交金额 - 推导费用
分红到账：正现金流 = 按权益事件及持仓推算的应收到账金额
区间期末：正现金流 = 期末持仓市值 + 尚未到账的分红应收
```

- 从已确认零持仓的建仓起点开始时，期初资产为零，不额外虚构一笔初始资金。
- 非零期初持仓使用区间初始市值，不使用历史成本替代。没有价格则相关收益不可算。
- XIRR 按自然日计算，同日现金流合并，期末估值只计一次；无正负现金流、无解或
  多解时返回明确状态，不随意选择某个根。
- XIRR 标为“资金加权年化收益”，不称为账户收益；短期样本优先展示盈亏金额、
  有效现金流跨度和数据状态，年化仅供辅助，不做短期年化排行榜。
- 买卖均已含费用，不能再从现金流中二次扣费。

### 6.3 分红应收、拆分与费用

- 使用核验的登记日持仓确认权益；除息日进入分红应收，派息日转为到账现金流。
  分红应收是资产，不是可用于下单的现金；已卖出仍可能有待到账权益。
- 分红按源事件和持仓推算，标记“按公开权益事件推算，未核对券商到账流水”；
  不宣称券商实收。拆分/折算调整数量与单位成本，总成本不能凭空改变。
- 显式无事件是有效结果；页面存在不等于已完成事件核验，结构解析失败也不等于无事件。
- 当前同步费用由成交/清算差额推导，源字段保留；不能由已被归零的 `fee_amount`
  证明没有异常。复盘检查缺值、方向、金额差和符号，无法核实的费用标记待核验。
- 费用覆盖若后续支持人工修订，必须留来源和修订前后值，不覆盖同步源字段。

研究佣金直接复用现有费率和最低佣金参数。例如“万一免五”设
`commission_rate = 0.0001`、`minimum_commission = 0`，即成交金额乘费率，
无需新增复杂模型。该费率是研究情景，不替代真实推导费用；佣金为零可作为
独立敏感性对照，不能隐藏有费结果，滑点仍单独记录且不因佣金低自动设零。

### 6.4 盈亏分解与曲线

以以下现金流恒等式验收，金额均为人民币元：

```text
区间净盈亏 = 期末资产 - 期初资产
           + 卖出净收入 + 分红到账 - 买入含费支出
资产 = 持仓市值 + 分红应收（不含无归属的闲置现金）
```

- 平均成本法下，已实现和未实现盈亏均已包含买卖费用；全历史从零建仓时：
  `累计净盈亏 = 已实现净盈亏 + 未实现净盈亏 + 累计分红权益`。
  费用单独披露为“已计入”，不再次扣减。子区间计算需扣除期初未实现盈亏及
  已确认的期初权益，且必须与上述现金流恒等式一致。
- 缺期初历史成本时，已实现/未实现成本分解标记不可算，仍可单独展示可核算的
  区间净盈亏；不拿首笔可见成交替代旧持仓成本。
- 真实图表展示日 K 与实际买卖、历史数量和累计净盈亏金额。累计盈亏不是净值，
  不从这条金额曲线计算最大回撤、年化波动或收益率。
- 没有成交的历史空仓期，累计盈亏可保持不变，待到账分红等权益继续处理。
  没有任何真实交易历史的标的显示“不适用”，不补零线。

核算验收样例：以 10 元买入 1000 份，佣金 1 元；再以 12 元卖出 400 份，
佣金 0.48 元；剩余 600 份期末收盘 11 元，无分红。买入含费支出 10001 元，
卖出净收入 4799.52 元，期末市值 6600 元，净盈亏应为 **1398.52 元**。
平均成本分解为已实现 799.12 元、未实现 599.40 元；费用 1.48 元已经计入，
不能再扣一次。

## 7. 标准化研究基线

本期复用现有策略与成交核算，提供同一标的的持有、MA20、MA60及零利息现金。
不新增独立策略页或另一套回测引擎。

- 四者使用相同研究资金、起止日、执行日历、费用、滑点、整手和权益事件。
  资金为研究名义资金，不代表实际给该 ETF 分配过的资金。
- 默认研究区间可沿用该 ETF 已核验真实交易区间，允许显式改选；未交易标的也可
  研究。实际结果和研究结果分别标明有效区间，不静默求不同起点后叠线。
- 持有在共同起点的首个可执行开盘建仓；MA 使用前一交易日及之前的信息，次日
  开盘执行。预热数据不足或行情缺口返回不可用，不自动让某条曲线晚起跑。
- 使用相同名义资金的研究组合保留空仓现金、分红应收、到账和期末持仓；现金不计息。
  允许生成研究净值、总收益和最大回撤，起点统一为 100。
- 权益源缺失或未核验时，本期完整基线不可用；仍可查看价格走势和明确标注的
  不含权益价格参考，但不与完整总收益混排，不据此输出“实际择时超额”。
- 新标的权益核验通过后扩展现有回测资格，资格按数据覆盖返回，不长期写死为两只。
  不能只新增前端选项而绕过后端权益、日历和快照校验。
- 记录研究范围及选取方式。用后来实际交易过的 ETF 回看过去，标为事后选择的
  研究范围；不能据此证明当时已具有选基能力。
- 比较同时展示区间收益、最大回撤、在场时间、换手与费用，不能只按收益判断有效。

## 8. 交易轮次与后续信号

本期先做可核算指标；信号日志、执行归因和更复杂统计分阶段增加。

- 一轮交易定义为持仓从零开始到再次归零。分批买卖属于同一轮，不能把分批卖出
  当作多次独立成功交易。未平仓轮次单列，不参与已完成交易胜率和盈亏比。
- 轮次持有期从首次买入到最终清仓按交易日计；期初已持仓但起点未知的轮次不猜天数。
  持有期分桶为 1–5、6–10、11–20、21–40、41–60、>60 个交易日。
- 每项统计显示完成、未完成和排除的样本数；一条委托累计成交不是多笔独立成交。
- 后续信号需记录规则版本、方向、生成时间、最早可执行时间、目标、取消/替代关系
  和记录方式。当时日志与事后重建分开，不从真实成交反推规则信号。
- 匹配要求同标的、同方向、信号在先且已可执行。允许一个信号多次部分执行，
  一笔成交最多关联一个信号；无精确时间的聚合委托不作精确延迟归因。
- 未关联成交、部分执行、完成、撤销、待确认分别记录。未成交不自动等于漏单，
  没有用户日志时也不把偏离 MA20/MA60 解释为用户执行错误。
- 后续信号后 5/10/20/40/60 个交易日收益从最早可执行开盘起算，并写明方向和
  价格/权益口径。不足观察窗口的样本标记未到期；重叠信号不当作独立证据。
  MAE/MFE 需约定持有窗口和可执行边界，日 OHLC 不推断日内高低先后或 T+1 当日可卖。

## 9. 接口与页面

### 9.1 已实现能力

继续复用当前接口和页面，不重建同步功能。

| 接口 | 当前能力 |
| --- | --- |
| `POST /account/sync` | 手动增量同步持仓和委托成交，返回批次与计数 |
| `GET /account/sync/status` | 最近批次及近期记录；不是完整历史无缺口证明 |
| `GET /account/holdings` | 当前配置内快照和本地收盘估值；权重只占配置内已估值持仓 |
| `GET /account/entrusts?start&end&instrument_code` | 委托成交展示，默认 30 天、最多 500 行 |

快照未实现盈亏沿用源成本价，属于持仓参考，不冒充按完整流水重算的净盈亏。
持仓快照和本地最新收盘可能不是同一时刻，保留各自日期，不称为实时市值。

### 9.2 复盘接口（已接入）

新增 `GET /account/review/{instrument_code}?start&end`，返回以下分区：

- `actual`：真实现金流、数量重建、净盈亏、XIRR、有效现金流日期、推算分红和
  推导费用、核算口径版本及输入摘要，以及各指标的可计算状态。未交易返回不适用，
  不返回假净值。源修订后重算显示版本/摘要变化，不冒充原计算结果。
- `research`：统一研究资金的基线结果或已保存实验引用、共同起止、费用、权益
  口径与输入摘要。可另传研究资金参数；不替用户分配真实资金。
- `quality`：同步区间、快照/行情/权益截止日、数量和金额差异、缺口及未解决事项。
- `comparability`：每个比较的资金、区间、权益和成本口径；不提供不可比的超额收益。

实际核算与研究模拟分开执行，单侧不可用不掩盖另一侧结果。复盘是按请求重算的
结果，不覆盖原始同步数据；研究实验仍按现有不可变输入/结果快照保存。

### 9.3 页面演进

在现有 `Review.tsx` 中增加单 ETF 复盘区，不新增重复持仓页。

```text
现有：同步状态 · 配置内持仓 · 委托成交
新增：紧凑标的/区间选择 · 数据准入状态
      真实结果：净盈亏/XIRR/费用/推算分红 · 日 K 与实际买卖
      规则研究：持有/MA20/MA60/现金 · 净值、回撤和交易成本
      数据质量与口径：按需展开
```

- 真实与研究分区，研究最多四线同图；不把实际盈亏金额塞入研究净值轴。
- 持仓和成交明细属于复盘操作功能，保留；行情/研究图表底下不重复铺数据表。
- 配置内全部标的可选；不依赖当前持仓和最近 500 行决定选项，已清仓和未交易
  标的均可进入研究，真实区显示相应状态。
- 加载、空、错误、过期、数据不足及不可比状态可见；中文、暗亮主题、键盘可用。

## 10. 验证与验收

已实现同步展示的验证与后续收益验收分开，不因本文修订声称重新验证外部接口。

| 阶段 | 必须通过的业务样例 |
| --- | --- |
| 权益和准入 | 有/无分红、仅拆分、解析失败；同步缺口、部分错误；跨日快照；数量不一致 |
| 真实核算 | 分批买卖、平仓后再入场、非零期初市值、无历史成本、区间外成交建立期初仓位 |
| 现金流 | 除息后卖出但分红未到账、起点已有应收、期末估值不重复、同日净额、XIRR 无解/多解 |
| 盈亏恒等式 | 费用只扣一次，轮次净盈亏合计与现金流核算一致，拆分不产生虚假收益 |
| 研究基线 | 相同起止、资金、权益和成本，预热不足不可用，空仓现金保留，历史样本池注明 |
| 统计与状态 | 分批退出仅算一轮、未平仓和未到期样本单列、无交易不是零收益、不可比无超额 |

后端运行相关业务测试、`ruff check app` 和独立测试库集成测试；前端运行
`npm run typecheck`、`npm run build`；编排按仓库约定检查。未执行的真实接口、
数据库和页面链路单独报告，不能由单元测试代替。

## 11. 分期、归属与依赖

功能主归属为“投资记录与复盘”，依赖数据基础和策略研究，不引入全账户账本。

1. **1A.1（已实现）**：配置内持仓＋委托成交增量同步、幂等、推导费用和展示。
