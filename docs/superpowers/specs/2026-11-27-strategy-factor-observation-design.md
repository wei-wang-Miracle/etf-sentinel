# 策略与因子观察架构

## 目标

把策略研究整理为“指标、因子、策略”三层，让用户只观察、理解和决策。指标由代码内部计算；因子是可观察的市场事件或状态，由代码实现并在行情图上展示；策略由代码组合因子并定义交易与风控规则。用户不创建或编辑因子、策略，不配置算法参数。研究由 AI/开发侧发起，结论留在研究记录和文档中，用户只查看有意义的结果并决定是否采用。

本次主归属为策略研究，行情图承担因子观察，盘前信号承接用户采用决策。此架构不引入自动研究代理、任意表达式、拖拽策略编辑器或全市场指标时序仓库。

## 术语与边界

- **指标**是行情及已核验权益上的数值计算，例如 MA、RSI、ATR、量比、收盘位置、动量、均线偏离和突破幅度。只存在于 Python 算法代码，不建指标目录表，不提供独立版本。
- **因子**是一个可复用的市场事件或状态，例如阶段底部确认、阶段顶部确认、MA5 上穿 MA20、箱体向上突破、放量向上突破、ATR 归一化超跌和超跌后的止跌修复。因子公式由代码计算；数据库保存身份、名称、分类、输出含义及关系，不保存可执行逻辑或因子版本。图表标记来自因果计算，不是买卖指令。
- **策略**是代码中以因子为组成部分的完整交易方法，定义因子关系、时序窗口、入场、退出、风险控制及执行口径。数据库保存策略身份和策略-因子语义关系，不保存可供选择的策略版本。用户可以比较当前策略并决定是否采用；新实验不会自动替换盘前信号。
- **指标、因子和策略均不得因重命名而掩盖公式变化。** 不做版本系统；语义发生变化时由代码与文档明确记录，旧实验快照仍保持当次证据，不冒充当前表现。
- **实验快照不是算法版本。** 每次策略比较保留当次策略身份、输入行情/权益、成本、触发轨迹、规则摘要和结果，用于解释该次实验；快照不能选择、启用或重新运行成历史算法。

## 首批因子分类

首批目录根据此前讨论的共享突破、左侧反转、顶底确认及多因子研究收敛。指标口径差异必须以实现为准，不因名称相似而混用。

| 因子身份 | 分类 | 输出含义 | 内部主要指标 |
| --- | --- | --- | --- |
| `turning_bottom` | 结构确认 | 因果状态机确认的阶段底部事件 | 标准化斜率、均线方向、ATR、区间突破与确认等待 |
| `turning_top` | 结构确认 | 因果状态机确认的阶段顶部事件 | 标准化斜率、均线方向、ATR、回落保护与确认等待 |
| `ma5_cross_ma20_up` | 趋势转折 | MA5 从下向上穿越 MA20 的当日事件 | MA5、MA20 |
| `box_breakout_up` | 突破事件 | 收盘首次超过此前 20 个交易日最高收盘 | 含息收盘、20 日历史最高值 |
| `volume_breakout_up` | 突破确认 | 箱体向上突破且量比达到当前代码固定下限的事件 | `box_breakout_up`、20 日量比 |
| `atr_oversold` | 超跌状态 | MA20 下方的负偏离达到 ATR14 的固定倍数 | MA20、Wilder ATR14 |
| `oversold_recovery` | 反转确认 | 近期超跌后出现因果定义的短线止跌/修复事件 | Wilder RSI14、ATR 负乖离、昨高突破、量比、收盘位置 |

状态型因子在状态进入日标记起点；事件型因子标记确认日。首期沿用现有顶底引擎作为 `turning_bottom` / `turning_top` 的计算来源，不改变其输出口径。其他因子使用含息因果价格；K 线显示使用对应交易日期，不用后续数据确认过去标记。量比为当日原始成交量除以前 20 个交易日均量，不含当日。Wilder RSI/ATR 的递推、预热、缺失和边界须有单元测试。

策略目录与关系：

| 策略身份 | 因子关系摘要 |
| --- | --- |
| `range_breakout` | 箱体向上突破为触发；趋势/放量等条件确认；顶底或 ATR 风险用于退出保护 |
| `bottom_confirmation` | 阶段底部确认为结构；动量、趋势与量能确认；顶部及其他风险用于退出 |
| `hybrid_reversal` | 底部、超卖或回落结构之一触发；动量、趋势和量能确认；风险因子控制退出 |
| `etf_multifactor` | 当前逐 ETF 规则使用其实际引用的底部/超卖/回踩/突破、修复、趋势、量能及估值条件 |
| `range_breakout_research` | 仅研究，不注册为现行策略；引用 `box_breakout_up`、趋势状态、收盘位置和量能确认 |
| `left_reversal_research` | 仅研究，不注册为现行策略；引用 `atr_oversold`、`oversold_recovery`、量比和 MA20 回归条件 |

实际触发关系以服务端代码为准。数据库策略-因子表只记录角色（触发、确认、过滤、退出/风险）和展示顺序，不承担条件求值；需要时间顺序、投票和阈值的完整语义必须在代码中实现并在策略说明中解释。

## 数据与调用流程

1. 指标代码只接受决策日及之前的数据和合格行情/权益输入，输出用于因子计算。
2. 因子计算器接受一段行情，输出 `(factor_id, trade_date, output)` 记录。图表 API 读取本地已核验数据后即时计算所请求区间；预热从区间前历史读取。缺失权益或质量校验失败时沿用现有明确错误，不返回伪造标记。
3. 因子目录 API 从数据库返回身份、分类、说明和关联现行策略；策略目录 API 返回策略身份、说明及因子关系。前端因子只提供展示开关和图表解释，不出现参数编辑、组合或因子买卖操作。
4. 策略比较 API 接受策略身份而非策略版本。服务端运行当前代码，并为每条轨道记录当次因子输出/触发原因、规则摘要、共同行情/权益输入和结果。关系表记录本次实验实际引用的因子。结果仍不可变，但不存在“选择历史策略快照”的入口。
5. 用户采用成功比较中的当前策略身份后，数据库对每只 ETF 保存单一当前策略分配；启用/暂停或替换是显式决策。每日信号用当前代码生成，并冻结当次行情、因子输出、决策理由和数据截止时间。算法变更不回写过去实验或信号，也不在没有用户决策时自动换用策略。
6. 研究迭代由 AI/开发侧通过代码和研究文档记录，不要求用户参与每轮研究，也不自动在用户界面暴露开发过程。

## 数据库设计方向

移除“算法多个可选版本”的存储概念，建立简单的当前策略与因子关系：

- `research_factors`：`factor_id` 主键、中文名称、分类、输出类型（事件/状态）、输出含义、是否允许行情图展示。
- 策略身份、名称、简介与可采用性由代码目录定义，不建立策略目录表。
- `research_strategy_factors`：代码中的策略身份、因子外键、使用角色和展示顺序；唯一约束防止重复关系。
- 每只 ETF 单条 `instrument_strategy_assignments`：当前选用策略和启停状态；不存在时表示未采用。
- `strategy_comparisons` 与回测结果继续作为不可变实验记录；新增关系表记录比较轨道实际使用的因子身份。JSON 输入/结果快照用于复核，不作为可选择版本。
- 每日信号保留当次证据快照；人工执行核对仍关联信号。迁移删除旧策略批次、保存版本、比较及相关轨道、信号和执行关联；原始真实委托和持仓不删。不承诺旧 API 或表兼容。
- 所有新业务表及字段写中文数据库 COMMENT；目录由迁移以稳定因子/策略身份初始化。代码目录和关系目录不允许静默不一致，测试需验证集合相符。

## 用户体验

- ETF 日 K 图提供因子标记显示开关，并用图例、悬停和说明文字区分底部/顶部确认、均线交叉、突破、超跌与修复事件；未勾选只隐藏图层，不影响策略计算。
- 因子说明包含名称、分类、输出含义、标记解释及“不构成买卖信号”。不展示内部指标阈值作为可编辑控件。
- 策略算法库与说明展示策略如何使用因子、买卖/风控流程和研究边界；比较当前策略和持有基准，提供采用/暂停/替换决策。
- 加载、无事件、权益缺失、预热不足、错误及数据截止状态明确可见；图表标记在键盘/悬停信息中可读。
- 不新增独立指标页面、因子配置器、策略编辑器、自动交易、自动启用、策略版本选择或用户可编辑算法参数。

## 迁移与旧行为

本次不保留旧策略版本流程。迁移清空本地旧策略域，保留未被旧比较引用的通用回测、行情、权益及原始账户数据。旧逐 ETF 多因子拟合不再作为现行算法；共享突破和左侧反转仍为离线研究，已登记可复用因子，不可采用。

## 验收条件

1. 代码目录定义的因子和数据库目录完全一致，类别、输出类型、说明可经 API 获取；关系 API 能查某个策略引用的因子及因子被哪些策略引用。
2. 首批因子事件按日序因果计算，覆盖预热不足、指标缺失、均线交叉边界、突破余量/成交量边界、RSI/ATR Wilder 初值和状态转事件去重。
3. 图表能按需显示上述标记，悬停说明身份和日期；隐藏/显示不影响回测信号。
4. 策略比较使用当前策略身份，保存所用因子关系与当次实验快照；回看实验不调用或伪装成历史可启用算法。
5. 每只 ETF 至多一条当前策略分配；用户明确采用、替换、暂停后才影响盘前信号；信号保留决策时证据，历史输出不会因代码后续修改而变更。
6. 空库和有旧数据的本机库可升级，破坏性迁移拒绝降级。旧策略版本路径从运行 API 与用户界面删除，不留兼容层。
7. 执行后端 lint/测试、前端构建/类型检查及浏览器测试、Compose 配置、迁移、文档链接和差异检查；实际迁移仅作用于用户授权的本机开发库，不访问生产。
