# 前端现状与痛点审计

本审计是[前端重设计](../../DESIGN.md)的证据底稿。
它区分代码事实、浏览器观察和设计判断，避免把个人审美当作用户需求。
审查日期为 2026-11-07，代码基线为 `a47ce11`。

远程更新检查遇到 GitHub SSL 超时，本次以本地代码为准，不声称已覆盖远程最新变更。

## 1. 方法与覆盖

先阅读 README、功能地图、设计契约、单 ETF 策略说明及现有前端代码，
再在已运行的本地前端检查实际页面。审查不启动或重启服务，不运行采集与回测。
独立浏览器会拦截 API 的 POST、PUT 等写请求，不操作真实策略及信号。

实际浏览环境为 Chromium，桌面 1440×1000、窄屏 390×844，默认缩放。
检查了桌面暗色的 ETF 列表、行情详情、真实操作、策略列表、策略编辑、横向对比、
任务页；另检查亮色行情及亮色窄屏 ETF 列表、行情、编辑、任务页。

导航、刷新、范围选中态及帮助展开另做实际交互检查。只读取当前本地数据，
不把账户数值或完整截图复制进设计文档；以下保留布局和行为观察，便于复核。

没有运行回测、启用、暂停、确认成交、同步账户、修改条件或手动生成信号。
当前样本没有已保存的单 ETF 策略和适用信号，因此比较结果与执行核对的诊断
来自代码审查，不能当作已完成真实业务全流程测试。

## 3. 可复核的布局观察

测量值仅代表本次数据样本、窗口和默认展开状态，后续数据变化可能改变高度。

| 场景 | 当前观察 | 影响 |
| --- | --- | --- |
| 桌面 ETF 行情 | 两个 `h1` 分别位于 y=80、326；图顶端 y=723，高 520px | 1000px 高首屏只看到图表上部 |
| 桌面真实操作 | 复盘图顶端 y=591，页面高 1426px | 核验、摘要和操作需要更清晰地分层 |
| 桌面策略编辑 | 尚无结果时页面高 2163px；比较区标题 y=1603 | 主要操作与规则输入分离过远 |
| 桌面横向对比 | 图顶端 y=621，页面高 1659px | 选择项、说明和概览共同挤压图表 |
| 窄屏行情 | 页面高 2138px；图顶端 y=1362、宽 260px | 侧栏、内边距和重复头部严重压缩证据区 |
| 窄屏编辑 | 页面高 3299px | 连续表单加说明成为长滚动任务 |
| 窄屏四个样本 | 文档宽均为 390px | 未发现页面级横向溢出，不能误报“移动端完全损坏” |
| 窄屏任务表 | 表格内容超出单屏但在局部滚动容器内 | 属于可接受模式，仍需固定关键列和滚动提示 |

上述七个桌面页面访问未捕获 `pageerror`，也未出现页面 `role=alert` 内容。
这仅说明当时读取路径可用，不证明写操作、异常恢复或业务计算正确。

## 4. 痛点清单

优先级按影响划分：P0 为对象或数据理解错误风险，P1 为主任务阻力，
P2 为一致性与阅读效率。它们是设计优先级，不等于后端缺陷定级。

| 编号 | 优先级／依据 | 具体发现 | 用户影响 | 拟议处理 |
| --- | --- | --- | --- | --- |
| A01 | P0／代码＋浏览器 | `App.navigate` 只写 `?page=…`；512100 详情切入我的策略，加载后选择变成159205 | 连续研究时可能配置错对象 | URL 显式携带对象，显示对象头；无对象时选取，不默选 |
| A02 | P1／代码＋浏览器 | `MyEtfs` 详情外层三个分区，`ResearchObject` 内层七个分区；重复标题和选择器 | 难以理解当前位置，图表下沉 | 合并外壳，图表维度与业务分区分清 |
| A03 | P1／代码＋浏览器 | `StrategyEditor` 五步静态列表始终给“配置规则” `aria-current`，内容却继续追加比较和保存区 | 不清楚进度及下一步 | 三阶段真实状态；编辑后旧结果显式失效 |
| A04 | P1／代码＋浏览器 | `DataManagement.tab`、`Jobs.task` 只在本地状态切换；从标的配置点账户后 URL 不变，刷新回标的配置 | 刷新丢位置，无法准确返回异常任务 | 分类和任务持久到 URL，重大导航使用历史记录 |
| A05 | P1／代码＋浏览器 | 当前持仓和全部 ETF 有 `aria-pressed`，但样式未关联；计算背景均为 `rgb(17,21,29)`，边框均为 `rgb(35,42,54)` | 不知道当前查看集合 | 统一分段选择组件及可见选中态 |
| A06 | P1／代码＋浏览器 | 聚焦买入条件的回看日输入后自动展开帮助；卖出区从 y=891 移到1219 | 键盘浏览导致布局跳动，长说明抢走任务焦点 | 固定说明区域或用户主动展开，保留已有十类指标解释 |
| A07 | P0／代码 | `MyEtfs` 三类请求使用 `Promise.all`；持仓为零时列表条件会展示全部 ETF，即使当前筛选仍是持仓 | 请求失败、未同步、真实空持仓容易被混淆 | 独立请求状态；空集合不回退，显式切换全部 |
| A08 | P0／代码 | `DailySignals` 零记录提示统一指向“保存并启用”，即使可能已有启用版本；待运行、无新触发、依赖阻断未形成同级模型 | 容易把未生成理解成没有策略，或把无新事件理解成失败 | 按证据区分配置、调度、依赖、适用日和执行状态 |
| A09 | P1／代码＋视觉 | 无策略时首页信号空区占约200px，仍突出“检查并生成”；完整信号在 ETF 和策略页重复铺开 | 新手先看到无效入口，熟练用户重复阅读 | 首页紧凑摘要，ETF 信号页承载详情，策略页只给状态链接 |
| A10 | P1／视觉＋数值计算 | 图表文字有9px末端标签；亮色下跌与恐惧色在纸面上分别约3.68:1、3.86:1 | 小字号和弱对比增加读数成本 | 提升文字色对比和字号，图形与数值分别验收 |
| A11 | P1／代码＋视觉 | 新页面多使用12px `.muted` 长说明；同一页面大量同权重按钮及带强调色链接 | 限制说明难读，重要操作难找 | 正文14px、辅助13px；每个任务一个主操作 |
| A12 | P1／代码 | ResearchObject 有完整 Tab 键盘逻辑，MyEtfs、DataManagement 不完整；Compare 虽有角色但缺方向键逻辑 | 同样外观带来不同键盘行为 | 统一 Tab 语义、焦点、方向键和面板关联 |
| A13 | P1／代码 | `ResearchChart` 对比序列混用 `p.greed/p.fear/p.up`；`StrategyComparison` 使用 `up/down` 类而 CSS 定义是 `market-up/down` | 对象身份、行情与情绪的颜色含义混乱，收益色可能不生效 | 独立曲线色板与统一数值语义样式，保留正负符号 |
| A14 | P2／代码＋视觉 | 390px 屏仍保留64px图标侧栏，图表容器再消耗内边距 | 可见图宽只有260px，日期与标记拥挤 | 窄屏用文字主导航，释放横向空间 |
| A15 | P1／代码 | 新详情仍有“因子”占位和通向旧研究的“策略”分区，Compare 有“因子（后接）” | 误以为未实现能力可操作，与新主流程争夺入口 | 移出主流程，旧实验留明确历史入口 |
| A16 | P1／文档＋代码 | 设计契约前部含旧色值、六只标的及未来模板，后部再覆盖；全局样式多次叠加同选择器并出现 `!important` | 后续页面容易继续分叉 | 新设计列出冲突处理；实施时归并受影响规则，不重写业务 |
| A17 | P1／视觉 | 真实成交标记在密集区遮挡K线，用户尚未选择复盘也会出现 | 行情结构难读，真实与研究边界不够突出 | 行情页主动叠加；复盘页聚合标记并保留逐次解释 |
| A18 | P1／代码 | 信号阻断“检查数据”链接只到数据管理默认分类，未定位依赖 | 用户还要判断该修复哪个任务 | 可识别原因映射到具体任务或账户权益区，支持返回 |

对 A07、A08、A12、A13、A15、A18 的异常状态没有制作虚假真实截图；结论来自
代码路径与现有文案。尤其 A08 只指出表达缺口，不断言实际任务调度失败。

## 5. 颜色检查记录

按 WCAG 相对亮度公式计算不透明前景与纸面背景的对比度，结果取两位小数。
小字标准为4.5:1；这是变量级检查，不是整站无障碍认证。

| 当前颜色组合 | 对比度 | 判断 |
| --- | --- | --- |
| 暗色 `ink-subtle #5C6678` / `surface #11151D` | 3.16:1 | 不适合作为必要小字 |
| 亮色 `ink-subtle #8C877E` / `surface #FAF8F3` | 3.36:1 | 不适合作为必要小字 |
| 亮色 `market-up #D92D20` / `surface #FAF8F3` | 4.55:1 | 仅该纯色组合达到小字标准 |
| 亮色 `market-down #079455` / `surface #FAF8F3` | 3.68:1 | 小字未达标 |
| 亮色 `sentiment-fear #0284C7` / `surface #FAF8F3` | 3.86:1 | 小字未达标 |

不能由此推出所有界面都使用了 `ink-subtle`；该项是变量使用风险。
重设计值与使用限制见[总设计](../../DESIGN.md)。

## 6. 保留的优点

重设计需要保留已有可信赖的能力，避免因简化视觉而删除业务解释。

- 三个主入口符合个人研究与数据维护的边界，无需再增加总览层。
- 中文条件、指标说明、买卖语句预览已经显著降低规则理解成本。
- 策略草稿与不可变版本区分，参数改变后旧结果不能直接保存，这些约束必须保留。
- 来源日期、复权未知、修订历史、真实与模拟分开等说明已有基础。
- 图表已有缩放、悬停、图注、双主题、缺失断线和关闭入场动画的能力。
- 源数据、五个任务及历史实验各自有明确边界，界面不能掩盖它们。
- 当前窄屏样本没有页面级溢出，改进重点是空间利用、层级和任务连续性。

## 7. 诊断到设计的追踪

未来评审可按下表检查设计是否回应实际痛点，避免只讨论颜色喜好。

| 问题组 | 设计落点 | 验收落点 |
| --- | --- | --- |
| A01、A04、A18 | 对象头、URL 上下文、修复返回动线 | 512100跨域保持、任务刷新恢复、返回草稿 |
| A02、A09、A14、A17 | 单层详情、摘要首页、窄屏布局、标记控制 | 图表首屏位置、宽度、信号唯一操作入口 |
| A03、A06、A11 | 三阶段策略、说明区、主次动作 | 变更后失效、帮助不推移桌面表单、主操作唯一 |
| A07、A08 | 数据及信号状态模型 | 失败≠空仓、无新信号≠调度失败 |
| A05、A10、A12、A13 | 共享控件、字体、语义色、键盘规范 | 双主题选中态、对比度、方向键、收益符号 |
| A15、A16 | 历史入口和契约迁移表 | 新主流程无占位入口，旧链接和结果仍可达 |

尚待后续实施验收的内容包括：有策略及信号数据时的真实页面、接口失败恢复、
长名称和多版本压力样本、屏幕阅读器、浏览器缩放、双主题全部图表及小屏完整编辑。
这些未验证项不影响本次提出设计，但不能在交付时写成已完成。

本次文档校验范围为三份新文件的本地链接、Markdown代码块、空白错误与设计一致性。
拟议的普通文字、必要控件边界、焦点及主按钮共108组双主题纯色搭配另做对比度检查；
不包含透明叠加、图表细线和真实渲染，因此不替代未来的页面验收。
