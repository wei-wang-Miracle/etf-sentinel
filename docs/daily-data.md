# ETF 历史日行情

提供标的配置、定时采集、日 K 展示及因子观察。初始范围见
[首期设计](superpowers/specs/2026-11-05-etf-daily-data-design.md)。

## 页面使用

1. **新增 ETF**：在「数据管理 → 标的配置」只输入六位代码。ETF 日行情源须在截至昨日的近 30 个自然日内返回有效记录，才能登记；无记录不代表该代码一定不是 ETF。重复代码不覆盖已有配置。新标的默认启用采集，起点为 `2020-01-01`，名称由行情源提供或在后续采集时补齐。
2. **采集与核验**：登记后尝试启动现有任务1，优先使用既有 ChatBI 采集日线并核验分红、份额折算；当 ChatBI 失败或未配置凭据时自动静默切换至分级免费行情源对比校验并补齐。对新增标的额外自动执行 `MAX(2006-11-27, 上市日期)` 至今日（15:30 收盘后含当日，盘中截至昨日）的早期免费历史回补。若已有任务运行，新标的会排队纳入下次任务1。可在「查看采集记录」核对各项结果。定时默认北京时间每日 01:00。
3. **查看因子**：在标的对应行进入「查看因子」，打开该 ETF 的日 K。因子只使用通过核验的行情及权益资料；没有数据、权益未覆盖、预热不足与区间内无标记含义不同。新增标的不自动建立指数估值或国家队映射，不创建或启用策略。

停用标的不删除行情，暂停定时不影响手动采集。配置修改不影响已开始运行的
配置快照，下次运行使用最新配置。调早历史起点会回补更早区间，调晚不删除历史。

## 数据处理口径

外部接口 `daily_ohlcv_etf` 用于新增代码核对及后台采集。行情图和因子读取本地 PostgreSQL。

- 首次从配置起点按自然月查询，成功区间单独提交。默认起点为 2020-01-01。
- 后续跳过已成功的旧区间，重查近期七日附近的交叠区间，并继续未完成月份。
- 失败区间不推进进度，下次任务重试；一只标的或月份失败不阻止其他区间。
- 行情与权益资料读取遇网络错误、HTTP 429 或 5xx 最多尝试三次；鉴权错误、
  非临时 HTTP 错误和权益表结构异常不作网络重试。
- 以代码和日期联合唯一约束更新行情，重跑不重复入库；源修订覆盖原值。
- 空响应保留请求区间和零条结果，不生成行情，不代表已验证数据完整。
- 入库前校验日期、标的、必要数值、价格高低关系；单个区间的数据统一校验后入库。
- 经至少两个独立免费数据源跨源审计确认共同无交易的停牌日（含份额折算停牌日），由迁移 0024 新增的 `instrument_verified_suspensions` 表持久化保存；在线因子图仅按「展示起点前推 266 个交易日预热窗口至截止日」校验连续性并放行已核验停牌日，未核验缺日仍严格拦截，且区分行情缺口与权益/复权错误提示。
- 当同一除权除息过渡期内同时存在已核验份额折算与现金分红（如 `159922` 于 2024-11-29 同日折算与派息）时，`validate_market` 与历史复权反推同时校验「先派息再折算」及「先折算再按折算后份额派息」两种合法理论倍数，仅当源复权因子在 `0.0004` 容差内精确匹配其一时方可通过，不放松单日误差校验。
- 数据库保留源原始开高低收及复权收盘字段。`GET /candles/{code}` 以
  `F_t = adjusted_close_t / close_t` 生成图表前复权 OHLC：
  `raw_ohlc_t × (F_t / F_end)`；因此所选区间末日仍为真实原始价格，已核验份额
  折算前后的图形连续。图表均线基于该展示序列，不参与策略决策。
- 顶底确认等因子使用因果复权 OHLC `raw_ohlc_t × F_t`，只依赖当日及此前已采集
  的数据；若量能指标使用成交量，仅按已核验份额折算反向换算，不把现金分红的
  含息复权倍率用于成交量。
- 回测、模拟成交和持仓账本继续使用原始价格。份额折算日不会调整模拟持仓份额，
  因而含折算区间仍拒绝回测，避免将错误净值呈现为研究结论。
- 成交量与成交额保留源数值，单位尚待数据源确认；不擅自转换为手、股或万元。
- 行情保存源更新时间和本地采集时间。最新入库日期不代表覆盖所有历史交易日。
- 行情阶段只处理启用标的；随后对全部配置标的逐只抓取并校验东方财富公开权益资料，
  停用行情采集不影响权益核验。每只权益快照独立提交；单只失败保留其旧快照，
  不回滚已成功行情或其他标的的权益更新，运行状态据此标记部分失败。
- 权益核验不依赖行情源令牌，但任务1的手动与定时入口仍需配置行情源令牌，
  因为同一任务还会执行行情采集。行情及权益结果分别写入任务运行明细。

API 内调度每 30 秒检查一次；当天已过执行时间且未运行时会补触发一次。
跨 API 进程使用 PostgreSQL 会话锁互斥，运行配置与日志存库。
应用重启将失去活跃锁的运行标记为中断，已成功提交的区间保留；
下次手动或定时运行继续未完成区间。应用未运行时不会执行定时任务。

## 环境变量与数据库

在根目录 `.env` 配置数据源凭据，保持该文件不被提交。

| 变量 | 说明 |
| --- | --- |
| `CHATBI_TOKEN` | Bearer token，仅填写 token 本体，不含 `Bearer ` 前缀 |
| `PGHOST` / `PGPORT` | 本地开发连接的 PostgreSQL 地址和端口 |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | 统一的数据库用户、口令与库名 |

本地 `.env` 只维护一套 `POSTGRES_*` 用户、口令和库名，不重复填写
`PGUSER`、`PGPASSWORD`、`PGDATABASE`。后端仍兼容 PG 变量，供独立测试库等
临时连接覆盖使用；同时设置时 PG 变量优先。
Compose 内会显式注入容器数据库参数，不使用本机 PGHOST 或 PGPORT。
固定 ChatBI 地址与行情、账户各自访问码统一由
`api/app/chatbi_config.py` 管理，不再通过环境变量覆盖；只有 token 放 `.env`。
资金号使用 Git 忽略的 `api/config/account.json`，示例见同目录
`account.example.json`。
数据源客户端直接连接目标地址，不继承系统 HTTP 代理，且不跟随鉴权重定向。

容器启动先执行 `alembic upgrade head`；本地开发需要手动执行迁移。
当前迁移创建标的、日行情、任务配置、运行记录和成功采集区间五张表。
后续语义命名迁移将物理列统一为明确业务名并添加详尽注释，见[数据库说明](database.md)。
迁移不连接外部行情源，不修改任何外部生产数据库。

## API

以下路径是 API 直连路径，前端访问时添加 `/api` 前缀。

| 方法及路径 | 用途 |
| --- | --- |
| `GET /instruments` | 配置与入库覆盖范围 |
| `PUT /instruments/{code}` | 保存 `enabled` 和 `start_date` |
| `GET /job` | 任务配置、下次执行时间和最近 20 次运行及区间日志 |
| `PUT /job` | 保存 `enabled` 和北京时间 `time`，格式为 HH:mm |
| `POST /job/run` | 异步触发，返回 202 和运行编号；已有任务返回 409 |
| `GET /candles/{code}?start=YYYY-MM-DD&end=YYYY-MM-DD` | 查询闭区间本地行情 |

## 分级免费历史回补

ChatBI `daily_ohlcv_etf` 仅覆盖至 `2024-08-12`，而投研回测与周期研究需要更长的历史行情。`api/app/free_market_sources.py` 与 `scripts/backfill_free_history.py` 提供基于 `MAX(2006-11-27, 上市日期)`（对齐交易所日历最早支持日 `2006-11-27`）的免费历史验证、回补与日常降级能力：

- **三级免费源**：优先东方财富（`fqt=0` 不复权全历史，含精确成交额与手→份换算）、备用新浪财经（`datalen=5000`，精确三位价格与份数成交量）、兜底腾讯财经（按两年分段拉取直达上市首日）。
- **可用前提下的对比验证**：
  1. **本地金标准重叠校验**：以本地库已有行情（如 `2024-08-12` 起）为锚，校验 OHLC（`<= 0.0001`）、成交量与成交额一致；
  2. **多源横向对比**：在全部可用免费源之间逐日对比共同交易日价格与日期覆盖；存在三源时通过多数一致消除单源早期畸变（如早年折算或熔断日差异）；仅两源可用且出现未消解大幅分歧时拒绝入库；
  3. **独立验证门槛**：必须同时具备本地锚或第二可用免费源交叉确认，禁止孤立单源盲写。
- **复权衔接与只增不改**：依据本地最早行情的 `adjusted_close / close` 锚点及已核验 `BacktestSource` 分红折算记录向历史反推 `adjusted_close`，使用 `on_conflict_do_nothing` 仅写入缺失历史日期（`source_updated_at` 记为 `free:<source>`），绝不覆盖既有 ChatBI 记录。
- **使用方式**：`api/.venv/bin/python scripts/backfill_free_history.py` 先做只读验证并输出 `.local/free-history-verification.json`，确认无误后附加 `--apply` 写入本地数据库。
