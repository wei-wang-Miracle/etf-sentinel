# ETF Sentinel

ETF Sentinel 是一个自用的 ETF 投研与买卖信号产生平台，初期关注宽基 ETF
择时研究，以及每日或信号驱动的买卖提示，辅助个人投资决策。

项目按实际使用需求逐步演进。已实现 20 只 ETF 的统一标的配置、历史日行情采集入库
和日 K 展示。开发协作约定见 [AGENTS.md](AGENTS.md)。

## 当前状态

当前以“我的 ETF、我的策略、数据管理”三个入口组织。共享算法、比较、ETF绑定及每日信号见[共享算法策略](docs/single-etf-strategies.md)，数据采集见[历史日行情说明](docs/daily-data.md)。

- 标的配置：原五只与国家队十八只去重，共 20 只，支持采集启停与历史起点设置。
- 定时任务：默认北京时间每日 01:00，支持手动运行、暂停、区间日志和失败重试。
- 行情展示：读取本地日 K 与成交量，支持 MA5/10/20/30/60、切换标的、日期范围、缩放及暗亮主题。
- 顶底指标：按跟踪指数将20只ETF分为大盘、中盘、小盘、微盘、创业板和科创板六类，各类使用独立历史拟合参数；行情图仍只标底部／顶部确认，并显示分类与规则依据。50轮配对模拟的总体胜率58.1%，近期诊断1/26；无一有足够证据证明80%，详情见[指标说明](docs/turning-points.md)与[50轮分类检验](docs/turning-points-validation.md)。
- 多因子汇总信号研究：本轮50次历史拟合结果为166/187胜（88.8%），近期已观察区间27/42（64.3%），前者属于旧逐ETF调参研究，不是共享算法的业绩、样本外验证或未来胜率保证；报告见[多因子汇总信号50轮检验](docs/multifactor-research-validation.md)。
- 顶底模拟：每只ETF独立50,000元，整手、次日开盘执行，计佣金、滑点及已核实现金分红；折算前行情不参与交易并从折算后重新预热。未平仓按净值计量且不进入已完成交易胜率，回测不代表实际交易。
- 行业恐贪：八类情绪着色概览、恐贪与指数双轴合图、紧凑概览与日期筛选；首次五年、后续增量采集。
- 国家队持仓：18 只 ETF 估算比例入库、增量写入，与统一采集的本地日 K 同图双轴对照。
- 指数估值：20只ETF关联8指数，五类日频估值、独立指数日K、来源分位与本地回看分位，图表对照；任务4每日01:30。
- 策略研究：在算法库选择标的、日期和算法，统一比较箱体突破、底部确认、复合反转与持有参照；选择项显示简述并可进入详细算法说明。算法规则直接随代码迭代，不提供用户可选版本、条件、参数、策略命名或费用配置。
- 模板算法：三套共享算法跨 ETF 使用当前规则，行情和权益按标的读取。历史按交易日期正序逐日处理，收盘决策、次日开盘模拟执行；历史记录保留内部规则快照用于复核。
- 交易诊断：完整平仓轮次计算胜率，期末未平仓单独列示；算法对比本金固定5万元，佣金万分之一、最低佣金0元、滑点5基点。每日信号模型成本与真实持仓成本分开，信号不等于成交。
- 模拟仓位：策略买卖点图以每日收盘仓位柱替代成交量，与日 K、买卖点和缩放联动；悬停及键盘读数查看仓位、份额、市值与现金，半资金按完整账户计算，缺失不补零。
- 投资复盘：手动增量同步配置内 ETF 真实持仓与委托成交，展示当前持仓、本地市值、推导费用和成交明细；另有单ETF净盈亏／XIRR准入核算及同资金持有、MA20／MA60、现金研究；不含配置外持仓、现金和全账户收益。
- 研究对象：仅以可交易ETF为主体，关联指数提供估值因子，分区汇总日K、五类估值、情绪背景、国家队比例、真实持仓和实验入口；URL恢复与图表懒加载。
- 横向对比：默认当前持仓，可切全部配置，按ETF比较关联指数估值、国家队比例与价格趋势；共享指数明确标记，不当作独立信息；行业情绪单列市场背景。
- 研究案卷：详情统一对象头、证据日期和“行情与背景／真实操作／每日信号”；跨导航保留 ETF 与日期，数据管理可返回原任务。行情、估值、国家队及情绪图支持悬停、缩放与键盘日期读数；不展示底部明细表。
- 图表维度：行情、关联估值、国家队、市场情绪采用横向标签，支持键盘切换与 URL 恢复；常规口径说明收在图表下方，国家队源未覆盖的 ETF 明确说明原因。
- 策略工作区：对比算法、核查逐笔原因和日K买卖点，保存成功结果才建立算法与ETF绑定；同ETF最多启用一个绑定记录，替换需确认。失败结果和持有参照不可保存。
- 回测研究记录：绑定详情和历史回测保留原始输入快照；算法修改后可用现行规则重测并保存独立记录，不改写原记录。旧逐ETF策略仍可复盘，已启用的可暂停。
- 数据库：PostgreSQL，Alembic 迁移，行情幂等更新并保留源更新时间和采集时间。
- 工程：React + TypeScript + Vite + ECharts、FastAPI、Docker Compose 三服务配置。

ETF 数据源仅提供历史日数据，采集截至昨日；不提供实时行情。
本地行情未声明复权口径，图上均线按源收盘计算并在图注标注“复权口径未确认”，
不把它当作前复权数据。
行业恐贪保留源日期，独立任务默认每日 01:10，无需 ChatBI 凭据；

## 本地一键启动（推荐）

安装 Docker、Python 3.12+、Node.js 22 后，在项目根目录运行：

```bash
./scripts/start-local.sh
```

脚本只用 Docker 启动 PostgreSQL，前后端运行在本机；自动准备 Python 虚拟环境、
安装依赖、运行迁移，然后启动前后端。前端默认 http://localhost:5173，
API 默认 http://localhost:8000/docs。按 Ctrl+C 停止本次启动的前后端，数据库保留。

在另一终端重启本地前后端：

```bash
./scripts/start-local.sh restart
```

无参数等同 `start`，保持前台运行。`restart` 等待旧启动器清理前后端后，
重新准备依赖、执行迁移并启动服务；未运行时直接启动，PostgreSQL 和数据保留。
重启后的服务由执行 `restart` 的终端管理，按 Ctrl+C 可停止。
同一项目禁止重复启动；进程状态保存在被 Git 忽略的 `.local/start-local.lock`，
使用系统文件锁和进程身份校验；身份查询固定语言及时区，支持不同终端环境重启。
遇到未知进程占用端口时拒绝启动，不按端口杀进程。
从不具备进程登记的旧版脚本升级时，先在原终端按一次 Ctrl+C，再使用新版启动。


首次自动创建 `.env`，填写行情源凭据后重新启动即可采集。
默认数据库宿主端口为 `55432`，可通过 `.env` 的 `PGPORT` 修改；
API 和 Web 端口分别由 `API_PORT`、`WEB_PORT` 设置，代理同步调整。
数据库用户、口令和库名统一使用 `POSTGRES_*` 配置，不再重复填写
`PGUSER`、`PGPASSWORD`、`PGDATABASE`；PG 变量仅供测试等临时连接覆盖。
如果本机指定数据库端口已有服务，脚本复用该连接并校验，不重启既有容器。
前后端端口被占用时明确退出，不杀既有进程、不自动切换到其他端口。
新建的 Compose 数据保存在命名卷 `postgres_data`；现有开发库可继续使用。

## Docker 三服务启动（可选）

需要 Docker Engine 和 Compose 插件。在项目根目录执行：

```bash
cp .env.example .env
# 编辑 .env，填写 CHATBI_TOKEN
docker compose up --build -d
```

在 `.env` 填写 `CHATBI_TOKEN` 后启动采集。
token 只保留在后端环境中，示例文件不含真实值。
账户同步另需复制 `api/config/account.example.json` 为同目录的 `account.json`，
填写字符串类型的 `fund_account`，保留前导零。本地启动和 Docker 共用此文件；
Compose 将配置目录只读挂载到 API 容器。已有本地资金号已迁移至该文件。
首次委托同步固定从 2025-01-20 开始，本地账户编号固定为 1。
容器 API 启动时自动迁移数据库；首次启动可能补触发当天到期的采集任务。

访问[前端](http://localhost:5173)和 [API 文档](http://localhost:8000/docs)。
通过 [Web 代理健康检查](http://localhost:5173/api/health)验证代理，或访问
[API 健康检查](http://localhost:8000/health)验证 API 进程。
健康检查只表示 API 存活，不检查数据库连接。
PostgreSQL 仅在 Compose 内网提供服务，数据保存到命名卷。
本地示例口令仅供开发使用。数据库连接参数通过 PGHOST、PGPORT、PGDATABASE、
PGUSER、PGPASSWORD 注入；迁移自动创建业务表及 20 只标的配置。

## 本地开发

前端需要 Node.js 22，后端需要 Python 3.12 或更新版本。
先准备可访问的本地 PostgreSQL，在根目录 `.env` 填写数据源及数据库连接参数。
后端启动前载入该文件，再分别在两个终端执行：

```bash
cd api
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
set -a
source ../.env
set +a
alembic upgrade head
uvicorn app.main:app --reload --env-file ../.env
```

```bash
cd web
npm ci
npm run dev
```

Vite 将 `/api` 代理到本地 API；容器内由 Nginx 提供相同代理。
数据库连接使用 `PGHOST`、`PGPORT` 等变量，详细说明见
[历史日行情说明](docs/daily-data.md)。
