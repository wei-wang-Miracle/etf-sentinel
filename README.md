# ETF Sentinel

ETF Sentinel 是一个自用的 ETF 投研与买卖信号产生平台，初期关注宽基 ETF
择时研究，以及每日或信号驱动的买卖提示，辅助个人投资决策。

项目按实际使用需求逐步演进。已实现 23 只 ETF 的统一标的配置、历史日行情采集入库
和日 K 展示。开发协作约定见 [AGENTS.md](AGENTS.md)。

## 当前状态

当前以“我的 ETF、我的策略、数据管理”三个入口组织。因子观察、策略比较、采用及每日信号见[策略与因子](docs/single-etf-strategies.md)，数据采集见[历史日行情说明](docs/daily-data.md)。

- 标的配置：预置 23 只 ETF，可在「数据管理 → 标的配置」输入六位代码新增。行情源确认后默认启用采集并启动现有任务，完成 ChatBI 行情回补与权益核验后，自动触发分级免费历史回补（按东财→新浪→腾讯补齐自 `MAX(2006-11-27, 上市日期)` 至今日的缺失日线）；完成权益核验后可从该标的直达日 K 查看因子。新增不创建或启用策略；仍支持调整采集开关与历史起点。
- 定时任务：默认北京时间每日 01:00，行情优先使用既有 ChatBI 数据，失败后静默切换为分级免费行情源对比校验并补齐；行情更新后批量核验全部配置 ETF 的分红与折算资料，逐项记录，支持手动运行、暂停与失败重试。
- 分级免费历史回补：针对 ChatBI 源仅覆盖至 `2024-08-12` 的早期缺口，通过[分级免费源](api/app/free_market_sources.py)（优先东方财富、备用新浪财经、兜底腾讯财经）抓取自 `MAX(2006-11-27, 上市日期)` 起的不复权日线，在可用源前提下执行本地锚重叠比对与多源横向一致校验后回补入库，并依已核验权益反推衔接历史复权收盘价（23 只 ETF 已验证回补，不覆盖已有 ChatBI 记录）；见[历史日行情说明](docs/daily-data.md#分级免费历史回补)。
- 行情展示：读取本地日 K 与成交量，以前复权 OHLC 连续展示已核验份额折算；支持 MA5/10/20/30/60、切换标的、日期范围、缩放及暗亮主题。顶底确认使用交易日可得的因果复权价格。
- 因子观察：行情日 K 默认标注阶段顶底与超跌后止跌修复，可叠加短均线上穿、箱体及放量突破等共 11 项事件或状态。图下显示核验截止日，权益不足可跳转更新。图层只影响展示，不修改算法或信号；详见[因子说明](docs/single-etf-strategies.md#因子观察)与[顶底因子](docs/turning-points.md)。
- 顶底参数研究：大盘、中盘、小盘、微盘、创业板和科创板模板来自既有50轮历史研究，属于统一因子的参数来源，而不是六套独立算法。该研究的配对模拟总体胜率58.1%，近期诊断1/26；无一有足够证据证明80%，详情见[指标说明](docs/turning-points.md)与[50轮分类检验](docs/turning-points-validation.md)。
- 多因子汇总信号研究：本轮50次历史拟合结果为166/187胜（88.8%），近期已观察区间27/42（64.3%），前者属于旧逐ETF调参研究，不是共享算法的业绩、样本外验证或未来胜率保证；报告见[多因子汇总信号50轮检验](docs/multifactor-research-validation.md)。
- 顶底模拟：每只ETF独立50,000元，整手、次日开盘执行，计佣金、滑点及已核实现金分红；折算前行情不参与交易并从折算后重新预热。未平仓按净值计量且不进入已完成交易胜率，回测不代表实际交易。
- 行业恐贪：八类情绪着色概览、恐贪与指数双轴合图、紧凑概览与日期筛选；首次五年、后续增量采集。
- 国家队持仓：18 只 ETF 估算比例入库、增量写入，与统一采集的本地日 K 同图双轴对照。
- 指数估值：20只ETF关联8指数，五类日频估值、独立指数日K、来源分位与本地回看分位，图表对照；任务4每日01:30。
- 策略研究：统一比较箱体突破、底部确认、复合反转与持有参照。指标、因子和策略规则在代码中，因子身份及研究关系入库；用户可查看解释，不生产、配置或编辑算法。旧逐 ETF 多因子和未达标的共享原型不进入可采用目录。
- 分类因子策略研究：冻结 23 只 ETF 的已核验行情、权益与指数映射，在不修改 11 项既有因子的前提下，按 9 个类别各完成 50 轮、共 1,350 个可解释表达式候选。研究按独立跟踪单位去重，使用连续持仓留出段、交易归因分账、压力成本和同成本买入持有比较；截至 2026-11-26 的校准结果没有任何类别候选可发布，因此未创建策略、绑定或每日信号。见[分类因子策略研究结论](docs/factor-strategy-research-2026-11-27.md)。
- 箱体突破研究：基于 20 只宽基 ETF 完成 30 轮离线优化，留出验证暂无标的达到 80% 胜率门槛。现行规则继续在算法库提供，详见[实证记录](docs/range-breakout-validation.md)。
- 共享择时固定先验验收：宽基共享突破与左侧反转使用 65 根预热、全期连续账本、分市况记分卡和参数高原检查；最新宽基与黄金、通信设备、半导体材料设备的冻结评估均显示回撤防守，但未通过上涨捕获或参数高原，未替换现行算法或盘前信号。跨资产输入目前仅覆盖 2024—2026 年；旧滚动寻优仅保留为历史复现。见[固定先验验收报告](docs/shared-etf-walk-forward.md)。
- 交易诊断：完整平仓轮次计算胜率，期末未平仓单独列示；算法对比本金固定5万元，佣金万分之一、最低佣金0元、滑点5基点。每日信号模型成本与真实持仓成本分开，信号不等于成交。
- 模拟仓位：策略买卖点图以每日收盘仓位柱替代成交量，与日 K、买卖点和缩放联动；悬停及键盘读数查看仓位、份额、市值与现金，半资金按完整账户计算，缺失不补零。
- 投资复盘：手动增量同步配置内 ETF 真实持仓与委托成交，展示当前持仓、本地市值、推导费用和成交明细；另有单ETF净盈亏／XIRR准入核算及同资金持有、MA20／MA60、现金研究；不含配置外持仓、现金和全账户收益。
- 研究对象：仅以可交易ETF为主体，关联指数提供估值因子，分区汇总日K、五类估值、情绪背景、国家队比例、真实持仓和实验入口；URL恢复与图表懒加载。
- 横向对比：默认当前持仓，可切全部配置，按ETF比较关联指数估值、国家队比例与价格趋势；共享指数明确标记，不当作独立信息；行业情绪单列市场背景。
- 研究案卷：详情统一对象头、证据日期和“行情与背景／真实操作／每日信号”；跨导航保留 ETF 与日期，数据管理可返回原任务。行情、估值、国家队及情绪图支持悬停与缩放；不展示底部明细表。
- 图表维度：行情、关联估值、国家队、市场情绪采用横向标签，支持键盘切换与 URL 恢复；常规口径说明收在图表下方，国家队源未覆盖的 ETF 明确说明原因。
- 策略工作区：对比策略、核查逐笔原因和日 K 买卖点。回测记录自动保存；只有用户明确采用后才生成后续信号。同一 ETF 只能采用一套策略，可确认替换或暂停。

## 本地一键启动（推荐）

安装 Docker、Python 3.12+、Node.js 22 后，在项目根目录运行：

```bash
./scripts/start-local.sh
```

脚本只用 Docker 启动 PostgreSQL，前后端运行在本机；自动准备 Python 虚拟环境、
安装依赖、运行迁移，然后启动前后端。前端默认 http://localhost:5173，
API 默认 http://localhost:8000/docs。按 Ctrl+C 停止本次启动的前后端，数据库保留。

在另一终端重启本地前后端：

```bash
./scripts/start-local.sh restart
```

无参数等同 `start`，保持前台运行。`restart` 等待旧启动器清理前后端后，
重新准备依赖、执行迁移并启动服务；未运行时直接启动，PostgreSQL 和数据保留。
重启后的服务由执行 `restart` 的终端管理，按 Ctrl+C 可停止。
同一项目禁止重复启动；进程状态保存在被 Git 忽略的 `.local/start-local.lock`，
使用系统文件锁和进程身份校验；身份查询固定语言及时区，支持不同终端环境重启。
遇到未知进程占用端口时拒绝启动，不按端口杀进程。
从不具备进程登记的旧版脚本升级时，先在原终端按一次 Ctrl+C，再使用新版启动。


首次自动创建 `.env`，填写行情源凭据后重新启动即可采集。
默认数据库宿主端口为 `55432`，可通过 `.env` 的 `PGPORT` 修改；
API 和 Web 端口分别由 `API_PORT`、`WEB_PORT` 设置，代理同步调整。
数据库用户、口令和库名统一使用 `POSTGRES_*` 配置，不再重复填写
`PGUSER`、`PGPASSWORD`、`PGDATABASE`；PG 变量仅供测试等临时连接覆盖。
如果本机指定数据库端口已有服务，脚本复用该连接并校验，不重启既有容器。
前后端端口被占用时明确退出，不杀既有进程、不自动切换到其他端口。
新建的 Compose 数据保存在命名卷 `postgres_data`；现有开发库可继续使用。

cd web

Vite 将 `/api` 代理到本地 API；容器内由 Nginx 提供相同代理。
数据库连接使用 `PGHOST`、`PGPORT` 等变量，详细说明见

## 验证

按改动执行构建、静态检查与业务测试。集成测试只允许独立的
`etf_sentinel_test` 数据库，并会清空该测试库中的业务表，禁止指定真实数据存储库。

```bash
cd web
npm run build
npm run typecheck
```

在安装后端开发依赖后，于 `api/` 执行：

```bash
ruff check app tests migrations
pytest -q
```

默认跳过数据库集成测试。准备独立测试库后，设置 `PGDATABASE=etf_sentinel_test`
及对应连接变量，执行 `alembic upgrade head` 和 `pytest -q`。
在项目根目录执行 `docker compose --env-file .env.example config --quiet`
检查编排配置。停止服务使用 `docker compose down`，命名卷会保留。

## 文档如何维护

每次新增、调整或移除功能，都在同一次变更中同步更新本文档。

- 当前状态只记录已实现能力，未完成或尚未验证的部分明确说明。
- 已确认的后续需求可以单独记录，探索想法保留在待讨论事项中。
- 功能新增或归属调整时，同步更新[功能地图](docs/feature-map.md)中的状态、
  依赖及设计或实现入口。
- 启动方式、依赖、环境变量、目录或验证命令变化时，同步修订对应章节。
- 长期协作规则变化时更新 [AGENTS.md](AGENTS.md)；详细方案放入 `docs/`
  并从本文链接，不在 README 中累积完整开发过程。
